# 프렛 × 가상 현 구역과 오디오 결합 작업 지시

사용자 승인: 2026-11-03 총괄 채팅에서 토론 후 “그래 일단 우리 토론한대로 작업 지시해줘”. 기존 코드 분석기 마일스톤을 유지하며 다음 기본 경로를 채택한다.

## 공동 결정

**지판·프렛 기하 → 6번 현 기준의 가상 현 구역 → 손 위치 분포의 칸별 질량 → 같은 시간의 오디오 호환성 → 운지/코드 후보**.

실제6현 직접 검출은 보조 근거로 남긴다. 매번 모든 현을 검출하는 것을 선행 조건으로 요구하지 않는다. 가상 현 번호는 실제 누름/발음의 정답이 아니며, 사용자가 검수한 첫 금속 프렛도 다른 번호·현·접촉을 확정하지 않는다.

3~12초 원본과 기존3개 오디오 창을 재사용한다. 새 run에 저장하고 기존 결과·사람 검수점·원시 좌표는 유지한다. 공용 코드·다른 담당 파일을 동시에 고치지 않는다. 먼저 각자 독립 fixture와 어댑터를 만들고 상류 실제 결과로 교체한다. 상류 부재 때문에 독립 작업까지 멈추지 않는다.

## 공통 계약

- 원본 MP4 SHA-256 source_id, frame_index, frame_pts_s, frame_pixel_sha256, 공통 캔버스·M/M_inv·grid_id/grid_version을 보존한다. 실제 원본·시간·좌표가 다르면 결합을 거부한다.
- `geometry_source`, `anchor_status`, `spacing_source`, `numbering_status`, `assumptions`를 전달한다. 미확인 튜닝·카포는 가정 또는 unknown으로 유지한다.
- 모든 구역은 `virtual_string_num`, `physical_fret_candidate`, `cell_id`, polygon/경계 모델, `estimated=true`를 갖는다. 상대 프렛은 카포를 확인하거나 명시 가정한 경우만 별도 제공한다.
- `contact=unknown`, `sounding=unknown`, `is_virtual=true`, `confidence_calibrated=false`를 기본으로 한다. 후보 위치 질량과 누름/발음 확률을 구분한다.
- 실제 현 검출 결과·가상 현 모델·화성 후보는 별도 레이어와 필드로 보존한다. 화면 TAB·코드 표기는 평가 참조만 허용한다.

## A. 지판·프렛·현 담당

소유: 신규 `virtual_string_grid.py`, `test_virtual_string_grid.py`, 자기 스키마·보고서, `dataset/virtual_string_grid/`. 기존 검출·기하 API를 재사용하며 손·오디오·화성 파일은 수정하지 않는다.

1. 6번 현 후보를 기준으로 가상 중심선6개와 현별 구역을 생성한다. 6번 현 검출은 쉽다는 보장은 없으며 실제 확인 여부를 기록한다. 지판 테두리/반사를 6번 현으로 자동 확정하지 않는다. anchor가 불명확하면 여러 모델 또는 보류를 제공한다.
2. 선 하나만으로 간격을 결정하지 않는다. 너트 쪽/바디 쪽 각각의 지판 폭·여백과 현 간격 가정을 설정으로 둔다. 너트 쪽과 바디 쪽에서 다른 간격을 허용한다. 숫자를 특정 코드 정답에 맞추지 않는다.
3. 공통 평탄 좌표에서 예를 들면 `y_k(x)=y_6(x)+(6-k)*d(x)`로 표현한다. `d(x)`는 양 끝 간격을 보간한다. 바깥 두 중심선 간 거리를 사용하면 간격은5개로 나눈다. 지판 전체를 무조건6등분하지 않는다.
4. 현 구역 경계는 인접 중심선의 중간이다. 최외곽 구역은 지판 유효 경계로 제한하고, 지판 밖은 별도다. 프렛n의 칸은 물리선n-1과n 사이이며 누락 경계·교차·미확정 번호는 출처/보류로 유지한다.
5. 기존frame120 의미검수와frame124/190/209~216을 사용해 원본/평탄 지판에 칸 이름·가상 선·실제 검출 선을 구분 표시한다. anchor·간격의 위치 민감도도 비교한다. 가상6현을 관측6현 성공으로 집계하지 않는다.

제출: 버전된 grid JSON과 같은 프레임 fixture, 그림 포함 보고서, 구역 중복/누락·좌우 방향·경계·기하 변화 검사. 현 간격 오차 수치는 정답이 없으면 미평가로 둔다.

## B. 손 담당

소유: 신규 `hand_cell_distribution.py`, `test_hand_cell_distribution.py`, 자기 보고서 및 `dataset/hand_cell_distribution/`. 가상 현 생성기는 새로 만들지 않고A의 계약을 받는다.

1. 기존 손끝 원형 가우시안→호모그래피 분포와 최신crop 근거등급을 사용해 프렛×현 구역별 질량을 적분한다. 원본 중심점 오류를 가상 칸이 해결한다고 주장하지 않는다.
2. 상위1/2/3칸, 칸별 질량, 지판 밖·미해결 기하·미배정 질량을 보존한다. 지판 내부로 재정규화해 잘못된 확신을 만들지 않는다. 한 칸에 몰려도 crop/full 충돌과 기하 보류를 지우지 않는다.
3. 가상선 간격과 손 위치의 불확실성을 혼동하지 않는다. anchor/간격 민감도 모델별 결과를 별도 보존하고, 가상선 불확실성을 실제로 전파했는지 명시한다. 고정6px는 보정 완료값이 아니다.
4. Kim의frame120 가시8점은 이미 검수됐으므로 재요청하지 않는다. 사람 좌표로 계산한 공간 칸과 모델 좌표의 공간 칸을 비교할 수 있으나, 둘 다 같은 추정grid에 의존하며 실제 접촉 현·프렛 정답은 아니다. 평가/검수 경로를 런타임 모델 좌표로 덮어쓰지 않는다.
5. 엄지·손끝·검지 마디를 구분한다. 바레는 여러 구역에 걸친 마디 위치 가설로 보존하며 각 구역이 실제 눌렸다고 하지 않는다. ROI-only는 미확정 후보 상태를 유지한다.

제출: 실제 프레임별 cell 후보JSON, 열지도·원본/평탄 오버레이, 직접 현 기반 이전 후보와 비교, 구역 질량 보존 검사. 실제정답 없는 top1/top2 정확도는 만들지 않는다.

## C. 오디오 담당

소유: 신규 `audio_cell_compatibility.py`, `test_audio_cell_compatibility.py`, audio 계열 보고서·산출물. 가상grid·손 분포·최종fusion 구현은 다른 담당 소유다.

1. Demucs v5 반주의 같은 시간창에서 후보cell→가능MIDI/Hz와 대조할 오디오 호환성 점수를 제공한다. 튜닝·카포·물리프렛 기준을 명시하고 카포 중복 가산을 방지한다.
2. actual spectral/지속 피크와 pitch-class-only 지원을 분리한다. 같은 pitch class라도 옥타브가 다르면 exact MIDI 일치로 표시하지 않는다. 각 점수의 evidence ID·시간 지지·cents 오차·배음/보컬stem 근접·악기귀속unknown을 보존한다.
3. 오디오 점수는 정규화된 호환성 지표이지 확정음 확률이 아니다. 미검출 음을0확률·뮤트로 단정하지 않는다. 결측과 약한/부재 근거를 구분한다.
4. 보컬 감소는 사용자 확인, 피아노 포함·기타단독 미확정 상태를 유지한다. 운지에 맞는 음이 피아노/배음일 수 있음을남긴다. 추가 모델 설치·다운로드는 이번지시에 포함하지 않는다.
5. 같은 창의 원음·반주·보컬 비교fixture를 화성 담당에게 제공한다. 새 입력이 준비되면 총괄보고에 정확한 경로·계약을 남긴다. 상류grid가 없으면 합성cell계약으로 시작하고 실제로 위장하지 않는다.

제출: 시간별 audio-cell 호환성JSON, 원음/반주 재생과스펙트럼 그림, 후보 선택 편향·출처 한계·회귀 결과.

## D. 화성 담당 — 칸 후보 결합과 코드 해석

소유: 신규 `cell_audio_fusion.py`, `test_cell_audio_fusion.py`, harmony 어댑터/스키마·보고서 및 `dataset/cell_audio_fusion/`. 손/음향 모듈 자체는 수정하지 않는다.

1. 같은 원본·시간·grid_version의 cell별 영상점수 V와 오디오 호환성 A를 연결한다. 물리 프렛·상대 프렛·가상 현을 구분하고 원래 관측은 보존한다. 입력 점수의 범위·정규화와 질량 손실을 문서화한다.
2. 실험 시작값은 `S=0.6*V+0.4*A`로 한다. 이는 휴리스틱 순위점수이며 누름 확률이 아니다. 영상의 확률질량과 오디오 피크점수는 동일한 확률이 아니므로, 이를 보정된 확률 결합이라고 보고하지 않는다.
3. 동일 자료에서 60:40, 80:20, 40:60과 영상 단독·오디오 단독을 비교한다. 음향·영상 최고 후보에 맞춰 구간별로 유리한 가중치를 고르지 않는다. 관측품질 가중치(예:70:30,30:70)는 조건·근거를 명시한 별도 실험으로만 다룬다. 기본 비율을 검증된 최적값으로 확정하지 않는다.
4. 둘 다 불량이면 판단을 보류한다. 한쪽이 결측이면 별도 단일 모달 결과로 표시한다. 누락 점수를 임의로 0으로 채워 상대 음·현을 제거하거나 조용히 재정규화하지 않는다. 영상이 보류됐는데 음향이 좋다는 이유만으로 실제 현·접촉을 확정하지 않는다.
5. cell별 상위 후보와 최종 운지 조합 가설을 분리한다. 같은 손가락을 동시에 서로 다른 칸에 배정하지 않는다. 같은 현의 상충 프렛·동시 발음·바레 가정은 명시한다. 서로 다른 현 매핑에서 유리한 음만 골라 합치는 오류를 금지한다.
6. 반주 화성·가상 운지 기반 코드 가설·확정 기타 코드를 별도로 유지한다. 동일 오디오로 만든 코드점수를 다시 독립 증거로 곱하지 않는다. 화면 정답·Kim 평가 결과를 런타임 fusion 점수로 누출시키지 않는다.
7. 비교지표는 상위 칸·조합의 순위 변화, 모호성, 보류, anchor·간격 민감도다. 실제 칸 정답이 없으면 적중률·오차율 개선을 주장하지 않는다. 검수 좌표 대조는 ‘같은 추정 grid의 공간 칸’ 지표로 별도 표시한다.

제출: 가중치별 비교표와 사진, 칸 열지도·근거 분해·최종 조합의 미확정 이유, 실제 상류 fixture를 연결한 재생 검사. 합성 자료는 합성으로 표시한다.

## 보고·통합 순서

A와 C는 즉시 독립 개발하고 B와 D도 계약 fixture로 병행한다. 실제 연결은 A→B, B+C→D 순서로 갱신한다. 필요한 자료가 준비되면 사용자에게 동일 검수를 반복 요청하지 말고 현재 자료로 가능한 작업을 진행한다.

모든 담당은 [사진 첨부 규칙](REPORTING_GUIDELINES.md)을 따른다. 사진·열지도·실패 사례를 본문에 삽입하고 가상 선과 관측 선을 색으로 구분한다. 완료·의미 있는 차단이 발생하면 자기 보고서를 갱신한 후 총괄 채팅 `01a19c25-9b62-71c2-b30c-3dc5c15966de`(local)에 직접 보고한다. 담당 간 파일 소유를 유지하고 기존 결과를 보존한다.
