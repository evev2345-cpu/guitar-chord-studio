# 오프라인 선확인(Look-Ahead Confirmation v2) 및 저음역 물리적 전위 분수코드 검증 보고서

**관련 모듈**: `chord_presentation.py`, `test_chord_presentation.py`  
**검증 산출물 경로**: `dataset/integration_review/runs/lookahead_confirmation_20261106_v1/`

## 1. 배경 및 문제 정의

기존 표시 후처리(`apply_chord_presentation_layer` v1)는 단일 프레임 단발 반전(`A -> B -> A`)만 정리하고, 새 후보가 인접 2프레임(`~0.083s`) 이상 나타나면 곧바로 표시 코드를 전환하는 **즉시 전환 방식**이었다. 또한 분수코드(전위) 억제 규칙은 중음역 내부 구성음 오검출(`Em/B`, `G/B`, `Cmaj7/G`)을 막기 위해 `presence >= 0.99`, `activation >= 0.72`의 초강력 기준만 허용했다.

이로 인해 실제 곡(녹황색사회 *Mela!* 튜토리얼 영상, 254초, 6,097 프레임) 검증에서 두 가지 한계가 확인되었다:

1. **동일 루트 확장음(`6`, `add9`, `sus2`, `sus4`, `maj7`) 및 미확정 단기 구간의 깜빡임**:
   - 예: `180.0s` (`G#`, 콘서트 `A`) 지속 구간에서 배음 흔들림으로 인해 `G# -> G#6 -> G# -> G#add9 -> G#sus2 -> G#`로 2초 동안 5회 깜빡임 발생.
   - 예: `90.0s` (`Am7`, 콘서트 `Bbm7`) 구간에서 `89.96~90.09s`(`0.125s`) 동안 일시적으로 튄 `Cmaj7` 스파이크가 그대로 노출됨.
2. **진짜 6번줄 저음 분수코드(`D/F#`)의 과도한 제거**:
   - 중음역 오검출(`Em/B` = 콘서트 `Fm/C`, `MIDI 48`)을 막는 과정에서 `144.0s`의 실제 `D/F#`(콘서트 `Eb/G`, 6번줄 3프렛 `G2 = MIDI 43`, `presence = 0.962`, `activation = 0.618`)까지 기본형 `D`(`Eb`)로 덮어써짐.

## 2. 해결 방법

### 2.1 오프라인 선확인(Look-Ahead Confirmation) 및 확장음 통합 (`offline_lookahead_confirmed_display_v2`)

전체 오디오를 끝까지 분석한 뒤 결과를 생성하는 오프라인 파이프라인의 특성을 활용하여, 앞뒤 문맥과 미래 구간의 지속 시간을 먼저 확인한 뒤 확정된 코드만 내보내도록 `chord_presentation.py`를 개선했다.

- **확정 최소 지속 시간(`confirm_s = 0.25s`, 24fps 기준 6프레임)**:
  - 전환된 코드가 스스로 `0.25s` 이상 유지되면 **시작 시점 지연(start delay) 없이** 원래 전환 시각 그대로 확정 표시한다.
- **다단계 샌드위치 구간 정리 (`A -> B1..Bk -> A`)**:
  - 확정된 앞뒤 코드 `A` 사이에서 잠깐 흔들렸다 돌아오는 다단계 구간을 통합한다.
  - 같은 루트의 확장음(`6`, `add9`, `sus2`, `sus4`, `maj7`)이 기본 코드 사이에 끼어든 경우 최대 `0.50s`까지 기본 코드로 통합(`consolidated_same_root_extension`).
- **미확정 단기 구간 흡수 및 전환 채터(Chatter) 브리징**:
  - `0.25s`를 채우지 못한 미확정 단기 구간은 인접한 확정 구간(`>= 0.25s`)이 해당 프레임 후보군에서 지지될 때 확정 코드로 흡수(`confirmed_lookahead_neighbor`).
  - 서로 다른 두 확정 코드 `A`와 `C` 사이에서 `0.17s` 이하로 끼어든 과도기 중간 코드 `B`는 후속 확정 코드 `C`로 브리징(`bridged_transition_chatter`).

### 2.2 물리적 6번줄 저음 전위 규칙 (`is_low_below_root_inversion`)

가짜 분수코드와 진짜 기타 베이스 워킹(`D/F#`)의 물리적 음역 차이를 정식 규칙으로 모델링했다.

- 표준 튜닝(`E2 = MIDI 40`) 기타에서 코드 루트(`root_pc`)가 낼 수 있는 최저 개방/프렛 루트 음높이는 다음과 같다:
  $$\text{lowest\_guitar\_root\_midi}(\text{root\_pc}) = 40 + ((\text{root\_pc} - 40) \bmod 12)$$
- **가짜 분수코드(`Em/B`, `G/B`)**:
  - 콘서트 `Fm/C`: 루트 `F`의 최저음은 6번줄 1프렛 `F2 (MIDI 41)`인데, 관측된 베이스 `C3 (MIDI 48)`는 루트보다 **높은** 5번줄 내성음이다 (`48 > 41` → 기각).
  - 콘서트 `Ab/C`: 루트 `Ab`의 최저음은 6번줄 4프렛 `Ab2 (MIDI 44)`인데, 관측된 베이스 `C3 (MIDI 48)`는 루트보다 **높은** 5번줄 내성음이다 (`48 > 44` → 기각).
- **진짜 저음 분수코드(`D/F#` = 콘서트 `Eb/G`)**:
  - 루트 `Eb`(`pc = 3`)의 기타 최저 루트음은 5번줄 6프렛/4번줄 1프렛인 `Eb3 (MIDI 51)`이다.
  - 반면 6번줄을 엄지/검지로 누른 `F#`(콘서트 `G2`)은 **`MIDI 43`**으로 루트 최저음(`MIDI 51`)보다 **8반음 낮다** (`40 <= 43 < 51`).
- 따라서 `40 <= bass_midi < lowest_guitar_root_midi(root_pc)`이고 `presence >= 0.90`, `activation >= 0.55`가 `0.20s` 이상 지속될 때만 저음역 전위 분수코드로 인정한다.

### 3.2 실제 영상 프레임 대조 검증 ① (180.0s `G#` 깜빡임 억제 및 144.0s `D/F#` 복원)

![Mela 180.0s 및 144.0s 검증](../dataset/integration_review/runs/lookahead_confirmation_20261106_v1/mela_180s_144s_comparison.png)

- **PTS `180.0s` (프레임 `#4316`, 화면 정답 `G#`)**:
  - 기존 `v1`: `178.8s ~ 180.3s` 사이에서 `G# -> G#6 -> G# -> G#add9 -> G#sus2 -> G#`로 5회 연속 깜빡이며 `180.0s` 정각에 `G#add9`를 출력함.
  - 신규 `v2`: 앞뒤 확정 코드가 `G#`임을 선확인하여 중간 확장음 흔들림을 단일 `G#` 구간으로 완전 통합함.
- **PTS `144.0s` (프레임 `#3453`, 화면 정답 `D/F#`)**:
  - 원시 문맥에서는 `143.2~143.5s`에 가짜 분수코드 `Em/B`가 함께 출현했고, 기존 `v1`은 이를 막기 위해 `Em/B`와 `D/F#`를 모두 기본형(`Em`, `D`)으로 제거했음.
  - 신규 `v2`: `143.2s`의 중음역 `Em/B`(`MIDI 48 > 41`)는 그대로 억제하면서, `144.0s`의 6번줄 저음 전위 `D/F#`(`MIDI 43 < 51`)만 정확히 복원함.

### 3.3 실제 영상 프레임 대조 검증 ② (90.0s 단발 스파이크 흡수 및 80.0s 미해결 한계 사례)

![Mela 90.0s 및 80.0s 검증](../dataset/integration_review/runs/lookahead_confirmation_20261106_v1/mela_90s_80s_comparison.png)

- **PTS `90.0s` (프레임 `#2158`, 화면 정답 `Am7`)**:
  - 기존 `v1`: `89.96~90.09s`(`0.125s`) 동안 튄 `Cmaj7`과 `90.09~90.21s`(`0.125s`)의 `C6`을 그대로 노출하여 `90.0s`에서 `Cmaj7` 오검출.
  - 신규 `v2`: `0.25s` 미만 미확정 구간을 뒤따르는 확정 `Am7` 구간으로 흡수하여 `90.0s`에서 정확히 `Am7`을 출력함.
- **PTS `80.0s` (프레임 `#1918`, 화면 정답 `F#m7` — 미해결 한계 사례)**:
  - `F#m7`(`F#-A-C#-E`)의 상위 3음(`A-C#-E`)이 `A major` 트라이어드와 완전히 일치하여 오디오 에너지 단독으로는 `A`가 `0.50s` 이상 우세하게 유지됨(원시 후보 2위가 `F#m7`).
  - 이 사례는 시간축 평활화만으로 해결할 수 없는 나란한조 모호성이며, 비전 기반 6번줄 근음(`F#`) tie-break 결합으로 해결할 항목으로 남겨두었다.
