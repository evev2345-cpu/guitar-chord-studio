# GUITAR 개발일지 — 2026-11-03 마감

시간 기준: Asia/Seoul. 사용자의 “오늘은 여기서 시마이”에 따라 신규 개발을 시작하지 않고 오늘 작업과 다음 착수점을 기록했다. 날짜 초반의 리뷰는 [기존 개발일지](DEVLOG_2026-11-03.md)에 별도 보존했다.

## 오늘의 결론

코드 분석기의 주요 모듈과 연결 경로는 구현했지만, **손가락 스켈레톤의 해부학적 대응 오류가 상위 운지·화성 결과를 왜곡할 수 있음을 확인했다.** 다음 개발의 우선순위는 가중치 조정보다 손가락 식별 검증이다.

직접6현 검출 중심에서 **프렛 × 가상 현 구역 + 손 위치 분포 + 오디오 호환성**으로 기본 방향을 바꿨다. 이 방향은 유지하되, 잘못된 손 중심을 정교한 분포나 가중치로 포장해서는 안 된다.

## 1. 담당별 구현과 연결

### 지판·프렛·현

- 사용자에게 너트·카포·첫 금속 프렛을 표시한 사진을 제시했고 “다 맞아” 확인을 받았다. frame120의 의미적 부품 구분과 첫 금속선=물리1번을 기록했다. 정밀 끝점·모든 번호·다른 프레임까지 검증한 것은 아니다.
- 최신 semantic 지판 결과를 손 관측과 같은 원본·PTS·픽셀 해시로 연결할 수 있도록 보존했다.
- 얇은 현과 지판 경계가 혼동되어 설정에 따라5~6개 선이 나오는 문제를 확인했다. 검출 개수6을 정답으로 강제하지 않았다.
- 6가지 여유 영역의 반복 후보·일시 후보·경계 모호 경로를 분리했다. 연속 8프레임의 내부선 5개는 추적 ID를 유지했지만 실제 물리 현 번호는 미확정이다.
- 6번 현 후보 anchor와 양끝 간격·여백을 가정하는 가상 6현 grid를 구현했다. 실제 11프레임×6모델=66JSON을 만들고 각 모델을 별도 시나리오로 유지했다.

![가상 현 기준선·간격 가정별 비교](../dataset/virtual_string_grid/runs/clip_003_012_20261103_v2/frame120_sensitivity_comparison.jpg)

가상 선은 검출된 실제6현이나 눌림 정답이 아니다. 그림의 배치 차이는 가정 민감도이며 실제 위치 오차 측정값이 아니다.

### 손 분석

- 다운로드 폴더에서 Kim의 기존 검수 JSON을 찾아 프로젝트로 가져왔다. frame120 한 장의9항목 중 가시8점·불명1점이며 원본/프레임/PTS/해시 검사를 통과했다. 이미 완료한 사진 검수를 다시 요구하지 않도록 정리했다.
- 가시8점 기준 기존 full 평균오차9.33px, 기존 ROI 평균오차22.84px를 확인했다. ROI가 항상 더 정확하지 않았다.
- 세 번째 오디오 창8.75~9.05초에서 full 모델이 운지 손 대신 피킹 손만 검출하거나 손을 모두 놓친 원인을 확인했다. 같은 프레임의 기존 ROI는7/8개에서 별도 손 후보를 제공했다.
- 확대 범위4가지의 새 추론44회로 공통 오류·범위 민감도·full과의 충돌을 분석했다. 다중crop 일치도 정확도 보증이 아니라 근거등급으로만 사용했다.
- 가상grid66개에 손끝/엄지 분포420개, 검지 마디 가설252개를 연결했다. 지판 안 재정규화 없이 밖/미해결/미배정 질량을 보존했다.
- 70개 관측 분기 중 22개는 grid 가정이 바뀌면 1순위 칸 주소가 달라졌다. 실제 접촉칸 오류율은 평가하지 않았다.

![전체 화면 미검출 시 확대 후보의 불일치와 보류](../dataset/integration_review/runs/robust_candidates_20261103_v2/frame_210_hand_reliability.png)

초록은 위치 후보, 빨강은 보류다. 이 그림의 손끝 이름은 모델의 식별 결과이며 아래의 최종 사용자 검수에서 오류가 지적됐다. 이 그림을 올바른 해부학적 손가락 정답으로 사용하지 않는다.

### 오디오

- 원본 보컬+기타 혼합, 분리 반주에서 보컬 감소 양호·피아노가 들린다는 사용자 청취 검수를 기록했다.
- 프로젝트 전용 `.venv-audio-separation`에 Demucs4.1.0·CPU PyTorch·NumPy와 공식 HTDemucs 모델을 설치했다. 기존 개발 Python은 유지했다.
- 실제3~12초9초 클립을 오프라인으로 vocals/no_vocals로 분리했다. 출력은44.1kHz stereo396,900samples로 입력과 일치했다. 약9.71초 실행은 이 짧은 클립의 측정값이다.
- 원음·반주·보컬의 같은 창3개, 총9개 음향fixture와 후보별 출처를 보존했다. no_vocals는 피아노를 포함한 반주이며 guitar-only가 아니다.
- 실제 가상grid18개×3성분=54건의 호환성 결과를 만들었다. exact주파수·PC-only·지속음 점수를 구분하고 악기귀속은unknown으로 유지했다.

![실제 가상 구역과 음향 호환성 대조](../dataset/audio_analysis/runs/audio_cell_actual_grid_20261103_v3/baseline/frame_124_audio_grid_overlay.png)

색은 조건부 음향 호환성이다. 그 칸을 실제로 눌렀을 확률이나 그 음이 기타에서 났다는 확인이 아니다.

### 화성·가중치 결합

- 실제 오디오 입력의 capo=null 크래시를 수정했다. 시간창별 증거와 반주·기타·미확정 출처를 분리했다.
- 실제 Demucs9개를 연결해 반주3창의 잠정 후보를 계산했다. 첫 창A♭add9/A♭maj7/A♭, 둘째Cm7/E♭6 동률, 셋째A♭maj7/A♭/Fm7 등으로 모호했다. 최종 기타 코드로 확정하지 않았다.
- 실제 A/B/C18건을 연결해 영상60:오디오40,80:20,40:60 및 단독모달을 비교하는 엔진을 구현했다. 실제 자료는 geometry=suspect·손 보류를 유지해 모든가중치에서 운지조합을 보류했다. 가중치 순위 변화는 합성계약에서 검증했다.
- 60:40은 실험 시작값이며 최적값이나 검증된 누름 확률이 아니다. 동일 오디오의 화성 결과를 다시 독립 증거처럼 중복 가산하지 않았다.

## 2. 마감 직전 확인한 핵심 오류

사용자가 frame210/PTS8.791667초에서 점·격자·분포 없는 기존 스켈레톤만 요청했다. 같은 프레임의 원시 ROI 단일손21점 전체를 EDGES로 연결한 사진을 받았다. 새로운 추론·좌표 보정·손가락별 medoid 혼합은 없다.

![사용자가 손가락 대응 오류를 확인한 원시 ROI 스켈레톤](../dataset/hand_skeleton_only/runs/frame210_20261103_v1/baseline_roi_hand_zoom.png)

사용자 검수:

> 엄지·검지까지는 괜찮지만, 중지 경로가 중지와 약지를 혼합하고 실제 약지는 소지로 표시됐다. 실제 소지는 누락됐다.

기록: `dataset/hand_analysis/human_review_20261103/frame210_finger_identity_review.json`.

이는 픽셀 위치의 작은 오차가 아니라 **손가락 체인 대응 오류**다. 따라서 해당 branch의 중지·약지·소지 칸 후보는 올바른 해부학적 운지 근거가 아니다. 예를 들어 소지1번현4프렛98.2%는 잘못된 중심 주위의 위치질량일 수 있으며 실제 소지 눌림 확률이 아니다.

다른crop·다른프레임까지 같은 오류라고 일괄 판정하지 않았다. 손가락 이름만 바꾸면 혼합된 체인이나 누락 소지가 복구되지 않는다. 원시 좌표를 보존했고 sidecar검수 정책을 기록했지만 **하류 전체run을 무효화·재계산하는 구현은 아직 수행하지 않았다.** 다음 착수에서 반드시 반영해야 한다.

## 3. 검증 기록의 해석

총괄이 직접 실행한 회귀는 초반59개, 통합대조93개, 실패진단97개, 확대/가장자리103개로 변화했다. 각 시점의 선택된 검사 집합 결과이지 합산 시험 수나 정확도 추이가 아니다.

후반 담당 보고 기준: A grid관련42개, B hand-cell관련115개, C관련58개, D관련116개(별도선택71개) 통과. 서로 겹치고 실행 시점이 달라 이를 모두 더하거나 하나의 최신 전역검사 결과라고 쓰지 않는다. 마감 문서 작성 과정에서는 새 개발·추론·전역 재검사를 실행하지 않았다.

단위검사 통과는 frame210의 손가락 대응이 옳다는 보증이 아니었다. 이 해부학적 실패를 직접 검증할 회귀가 추가로 필요하다.

## 4. 다음에 다시 시작할 순서

1. **손가락 체인 오류를 최우선 고정 회귀로 등록.** frame210의 원시 skeleton·사용자 검수·입력 해시를 보존하고 해당 branch의 잘못된 손가락 근거를 하류에서 제외/보류한다. 엄지·검지의 정성 확인을 정밀좌표·접촉 정답으로 확대하지 않는다.
2. **같은 프레임의 단일손 전체21점끼리 비교.** 가림·crop에 따른 손가락체인 혼합과 누락을 살핀다. 손가락별 좋은 점을 이어 합성 스켈레톤을 만들지 않는다. 원본/스켈레톤 사진을 함께 보고한다.
3. **손 신뢰도가 확보된 branch로 칸 분포 재생.** 원래위치·새가설·제외근거를 분리하고 바레·소지누락을 정상 상태로 유지한다. 가상현 위치 민감도도 함께 표시한다.
4. **그 뒤 음향·가중치 재대조.** 피아노/배음과의 우연한 일치,미확인 튜닝·카포를 유지한다. 틀린 손을 오디오/정답코드로 억지 보정하지 않는다.

우선순위는 **손가락 식별 → 칸 후보 안정성 → 오디오 보완 → 코드 후보 평가**다. 오늘은 여기서 마감하며 신규 담당 작업 지시나 새 실험은 시작하지 않았다.
