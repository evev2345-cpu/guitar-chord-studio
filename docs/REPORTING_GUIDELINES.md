# 개발 보고서 작성 규칙

사용자 요청(2026-11-03): 앞으로 개발 보고서에 사진을 함께 첨부한다.

- 영상·손·지판·현 관련 보고서는 해당 원본 프레임과 분석 오버레이 또는 변경 전후 사진을 본문에 삽입한다. 사진 경로 링크만 나열하지 않는다.
- 각 사진에 프레임 번호·실제PTS·원본/관측/추정/사람검수 구분과 색상 범례를 붙인다. 실패·미확정 사례도 포함한다.
- 음향 보고서는 관련 원본/처리음 재생 자료와 파형·스펙트럼 비교 이미지를 넣는다. 화성 보고서는 시간에 대응하는 화면/시각화와 후보 비교를 넣는다. 관측에 없는 사진을 만들지 않는다.
- 검사 근거 사진은 원본 픽셀에서 코드로 재현 가능한 시각화를 사용한다. 생성형 편집 사진을 정밀 좌표·성능 정답으로 사용하지 않는다.
- 그림의 화살표·선·색은 검출 근거와 정답을 구분한다. 사람이 검수하지 않은 후보는 ‘확정’으로 표시하지 않는다.
- 본문에 검증 명령·실제 결과·한계·다음 작업을 적고 사용한 그림이 실제 파일로 존재하는지 확인한다.
- 최종 채팅 보고에도 가장 중요한 비교 사진을 가능하면 하나 이상 표시하고 전체 보고서로 연결한다. 파일 위치는 절대 경로 링크를 쓴다.

문서·계약만 바뀌어 관련 사진이 없는 경우는 실제로 바뀐 계약 예시/비교표로 설명하고, 무관한 사진을 채워 넣지 않는다.
