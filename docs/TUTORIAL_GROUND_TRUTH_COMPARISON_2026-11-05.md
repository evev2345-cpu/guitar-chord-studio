# 화면 코드·TAB·실제 운지 대조 후 코드 정확도 비교

후속: 같은9개 구간의 [기타 분리 트랙 대 기존반주 비교](GUITAR_STEM_ACCURACY_COMPARISON_2026-11-05.md).

**안정 구간9개에서는 오디오 단독과 탐색 통합80/20의 정확도가 같았다. 정확한 코드1위2/9(22.2%), 상위3개 포함6/9(66.7%), 근음 일치8/9(88.9%)다. 손 위치 추가로 정확도가 개선된 사례는 없었다.**

## 이전 표본의 문제와 새 표본

이전18시점은 손 검출 실패·선택 보류 등을 진단하려고 고른 시점과 그 주변이어서 일반적인 코드 판별 정확도 표본으로 부적절했다. 전부 코드 전환은 아니지만 전환/검출 난해 구간이 섞여 있었다. 새 표본은195~225초를2초 간격으로16곳 먼저 훑고 원본 운지와 화면 다이어그램/TAB를 확인했다. 예측 성능을 보고 표본을 고르거나 가중치를 바꾸지 않았다.

중앙과±5프레임(약0.208초)의 사진에서 운지 이동이나 현재 코드 표시 변경이 확인된201/203/205/213/215/217/219초7곳은 보수적으로 제외했다. 나머지195/197/199/207/209/211/221/223/225초9곳을 안정 구간으로 사용했다. 세 장의 시각검사 기반이며 모든 실제 현 접촉을 검증한 것은 아니다.195·199·207초처럼 같은 코드가 반복되므로9개 독립 코드 종류로 해석하지 않는다.

## 정답의 의미

원본의 화면 코드명·TAB·다이어그램을 읽고, 너트/카포와 실제 손의 위치·형태를 대조한 **에이전트 시각검수 참조 정답**이다. 별도 사람이 독립 검수한 외부 정답 데이터는 아니다. 가려진 현 접촉이나 기타만의 실제 발음까지 정답으로 확정하지 않는다. 화면 표시의 다음 코드와 현재 운지를 구분했다.

Capo.1이 표시되고 카포가 첫 물리프렛 공간에 있으므로 TAB 운지는 카포 기준으로 읽었다. 표준튜닝을 전제로 화면 F#형244322는 실음 G, Fm형133111은 실음 F#m, F7형131211은 실음 F#7, G#형466544는 실음 A, G#7형464544는 실음 A7, A형x02220은 실음 Bb로 이조했다. 계산 코드의 Gb는F#, Gbm은F#m과 같은 근음으로 채점했다. 튜닝을 독립 청음으로 확인한 것은 아니다.

`references.json`에 원본 이미지/프레임/실제PTS, 화면 코드형과TAB6→1, 카포, 실음 코드, 검사한 앞뒤 프레임과 제외 사유를 예측 전에 저장했다. 정답 라벨은 모델 점수·후보 생성·가중치에 전달하지 않았다. 전체 화면 손 모델에 보이는 화면 글자를 OCR로 읽어 예측하는 경로도 없다.

## 같은 조건의 오디오 단독 대 통합

기존 로컬 Demucs194~226초 반주와 같은 화성 사전/점수를 재사용했다. 각 중앙 시점의±0.2초에 STFT 분석창 전체가 포함되는22개 분석 프레임을 골랐다. 음고류를 시간에 걸쳐 합집합으로 모으지 않고, 각 분석 프레임의180개 코드 점수를 따로 계산한 뒤 같은 코드의 점수를 평균했다. 이 안정구간 평균을 주평가로 사용했다. 기존처럼 중앙에 가까운 단일 STFT 프레임으로 평가한 결과도 별도로 저장했다.

시각은 중앙 원본에서 현재 원본우선/조건부회전 손 선택을 실행하고, 잠정 지판·가상현의 검지/약지/새끼 끝 질량으로 호환성을 계산했다. 중지는 기존처럼 제외했다. 이전과 같은 반경12픽셀, 현간격기본가정, 오디오0.8/시각0.2를 유지했다. 정답을 보고 가중치를 조정하지 않았다. 결과는 탐색 통합이며 기존 운영의 미확정 해부학/기하 차단을 해제하지 않는다. 엄격한 차단을 유지하는 결과는 오디오 단독과 동일하다.

## 무엇이 부족한가

근음은8/9에서 맞지만 major/minor와7/maj7/add9 등의 구분이 약하다. 현재 오디오 점수는 코드 구성음의 salience coverage를 크게 반영하므로 반주/배음의 추가 음을 포함하는 확장코드가 높은 점수를 얻을 수 있다. 이번 반주는 기타 단독이 아니고 다른 악기 소리가 포함될 수 있으므로, 화면의 기타 코드와 혼합음 화성은 다를 수 있다. 단순 스펙트럼 점수의 한계와 악기 혼합 영향을 분리 평가해야 한다.

시각 점수도 손끝 몇 개가 후보 구성음에 포함되는지 중심이라, G와Gmaj7처럼 많은 음을 공유하는 후보를 잘 구별하지 못한다. 실제 접촉/개방현/바레 발음을 모르기 때문에 손 선택만 좋아졌다고 화성 정확도가 자동으로 높아지지 않았다.207초에서는 정답G 순위가2위→3위로 내려가기도 했다. 상위3개 포함 수가 같다고 모든 순위가 좋아진 것은 아니다.

다음 우선순위는 가중치 증가보다 **불필요한 확장음에 대한 오디오 점수 검증, 저음/근음 근거, 기타와 다른 반주의 영향 분리**다. 손끝/접촉을 정답으로 가정해 코드를 강제로 고치지 않는다. 이9개에 맞춰 튜닝한 뒤 같은9개로 성능 향상을 주장하지 말고 별도 구간에서 재검사해야 한다.

## 재현과 검증

`python review_tutorial_stability.py`로 원본 전후 비교사진을 생성하고, `python evaluate_tutorial_reference.py`로9개 구간을 평가한다. 최종 결과가 있으면 덮어쓰지 않는다. 결과폴더는 `dataset/integration_review/runs/tutorial_accuracy_20261105_v1`이며 정답JSON/전체180개 후보/평가metric/손·지판 근거/원본 해시를 보관한다. 정답JSON과 오디오 입력SHA256도 결과에 저장했다.

새 테스트는 TAB+카포의 음고류가 정답 코드와 일치하는지, 확장코드를 정확한 삼화음 정답으로 잘못 세지 않는지, 두 방식이 같은9개 표본과 고정가중치를 쓰는지, 저장metric이 프레임별 평가와 일치하는지 검사한다. 이 정답검사는 기타 실제발음의 독립 전사 검증을 대신하지 않는다.

검증 명령: `python -m unittest test_tutorial_reference_evaluation test_new_hand_harmony test_harmony_engine test_cell_audio_fusion test_hand_cell_distribution test_virtual_string_grid test_global_fretting_hand -q` —82개 통과.
