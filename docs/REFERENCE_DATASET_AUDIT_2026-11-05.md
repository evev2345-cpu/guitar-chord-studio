# GuitarSet·EGDB 로컬 구성 검사

현재 프로젝트 폴더만 검사했다. 추가 데이터 다운로드나 학습은 실행하지 않았다. 사용자가 말한 EGDBpro에 해당하는 것으로 확인한 실제 폴더명은 `EGDB_repo`이며, 별도 EGDBpro 이름의 루트 폴더는 없었다.

| 대상 | 실제 로컬 내용 | 부족한 것 |
|---|---|---|
|GuitarSet|JAMS360개, annotation.zip, 공식 저장소와 도우미|대응 WAV/FLAC 등 녹음 음원 없음|
|EGDB_repo|논문 데모 사이트 저장소, WAV18개|대응 MIDI/음표/코드 정답 파일 없음|

## GuitarSet

전체360개 JAMS를 JSON으로 읽어 확인했다. 반주(comp)180개, 솔로180개, 파일명 연주자ID00~05 각60개다. 주석의 녹음 길이 합계는10,968.44초(약3.05시간)이며 로컬 음원 길이를 측정한 것은 아니다. 줄별 note_midi 트랙은6×360=2,160개이고 총 음표 이벤트62,476개다. 시작시간/길이/소수 MIDI 피치/줄ID가 있다. 표준튜닝을 전제로 줄ID와 MIDI를 이용해 프렛 후보를 계산할 수 있으나 실제 손가락/손 관절 라벨은 아니다.

모든 파일에 chord 주석이 두 층씩 있다. 각 층의 구간 라벨은4,320개다.

1. 악보/진행에 대응하는 기본 코드 층. 예: `D#:maj`.
2. `Semi-automatic chord transcription with manual verification`으로 명시된 상세 연주 코드 층. 주석 규칙은 줄별 음 전사와 악보의 분절/근음을 이용한다고 설명한다. 예: 같은 파일의 한 구간이 기본층 `D#:maj`, 상세층 `D#:maj7/1`이다.

이 차이는 지금의 G 대 Gmaj7 문제에 직접 관련된다. 화면/악보의 간략 코드와 실제 연주 음을 기준으로 한 상세 화성을 같은 정답으로 취급하면 모델이 실제 추가음을 찾은 경우도 오답으로 셀 수 있다. 반대로 배음을 별도 기본음으로 오인할 수도 있으므로, **음표 정답으로 기본음 검출을 평가하고 코드 두 층은 별도로 평가**해야 한다. 이번 튜토리얼에서 Gmaj7 예측이 실제로 옳다는 뜻은 아니며, 그 원인을 분리 검증할 수 있다는 뜻이다.

아래는 로컬 `00_BN1-129-Eb_comp.jams`를 그대로 그린 실제 주석 예시다. 위는6개 줄별 MIDI 음표, 가운데 기본 코드, 아래 상세 코드다. 음원은 없어서 새 오디오 전사 결과를 만든 것이 아니다.

![GuitarSet 음표와 두 코드 주석층](../dataset/integration_review/runs/reference_dataset_audit_20261105_v1/annotation_example.png)

기존 `GuitarSet/inspect_jams.py`는 chord 주석의 출처를 구분하지 않고 두 층을 같은 목록에 추가한다. 평가용 어댑터에서는 이를 분리해야 한다. 소수 MIDI 값은 미세 피치 정보를 유지하고, 프렛 추정용 반올림값과 구분하는 편이 적합하다. 상세 Harte 코드 표기는 `sus2(7)`, `maj6(*5)`, 추가/누락음·베이스 표기를 포함하므로 현재 유한 사전에 없는 라벨을 억지로 단순화해 정답으로 세지 않아야 한다.

공식 로컬 README에는 두 주석의 시간 오류와 MIDI 중복음에 관한 알려진 이슈가 안내돼 있다. 검증셋 구성 시 해당 파일/버전 확인이 필요하다. 현재 받은360개가 해당 수정 전후 어느 버전인지까지 검증하지 않았다.

## EGDB_repo

로컬 Git origin은 `https://github.com/ss12f32v/Guitar-Transcription.git`, 브랜치는 gh-pages다. 전체 연구 데이터가 아니라 논문 데모 사이트 체크아웃이다. 로컬 index.md는240개 tablature와 여러 tone을 설명하지만, 그 전체 파일이 현재 디스크에 있다는 뜻은 아니다.

- Training8개: 서로 다른2개 예제의 DI/Marshall/Fender-twins/Mesa 음색 각4개.
- RealData5개: 현실 녹음 예제.
- RealDataTranscription5개: 사이트에서 Proposed model로 표시하는 재생용 출력. 정답 MIDI가 아니다.

WAV는44,100Hz이며 DI는 모노, 나머지는 스테레오다. 같은 Training 예제라도 DI와 앰프 처리 파일 길이가 다르다.0503 예제는25.600초 대26.018초,0701 예제는20.572초 대20.817초다. 음색 비교 시 단순히 같은 샘플 인덱스라고 가정하면 안 된다. 주석/정답 파일을 받기 전에는 데모 모델 출력이나 파일명으로 정답을 만들어 정확도를 주장할 수 없다.

## 활용 판단

현재 우선순위는 **GuitarSet의 대응 음원 확보 후, 반주180개를 중심으로 기본음/배음 구분과 코드 종류 평가를 구축**하는 것이다. 데이터셋의 이미 제공된 음표/상세 코드 정답을 사용하면 영상9개에만 맞춰 가중치를 고르는 문제를 줄일 수 있다. 같은 진행/연주가 분할에 중복되지 않도록 연주자·진행 단위 분리도 검토해야 한다.

EGDB는 대응 MIDI/음표 정답을 포함한 본 데이터를 확보하면 음색 변화에 대한 추가 검증에 적합하다. 로컬 데모 음원만으로는 정량 평가가 완성되지 않는다. 다운로드 링크는 각 로컬 README/index.md에 있지만 이번에는 따라가서 다운로드하지 않았다.

**두 로컬 구성 모두 영상/손 관절 정답은 없다.** 따라서 오디오 판별기 검증에는 유용하지만 실제 비전:오디오2:8을 직접 최적화하는 A/V 검증셋은 아니다. 정답 운지를 가상 비전으로 넣는 실험을 하더라도 실제 손 검출 성능과 구분해야 한다.2:8은 아직 작은 튜토리얼 개발 표본의 후보 설정이다.

재현 명령: `python inspect_reference_datasets.py`. 파일 종류/수/바이트, JAMS 통계와 WAV별 길이/채널/샘플레이트는 `dataset/integration_review/runs/reference_dataset_audit_20261105_v1/inventory.json`에 저장했다. 검사 스크립트는 원본 폴더를 수정하지 않고 별도 감사 산출물만 작성한다.
