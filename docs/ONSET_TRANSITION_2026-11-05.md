# 온셋·구성음 변화 가점 연결 — 2026-11-05

사용자 요청에 따라 기능을 연결하고, 음악적 정확도·사용감 검수는 사용자에게 남겼다. 기존 저장된 Basic Pitch의 `onset` 출력을 사용하며 새 추론이나 모델 학습은 하지 않았다.

## 사용법

웹앱을 새로고침하고 기존 Mela 결과를 다시 연다. **‘저음·화성 가점 적용’을 켠 상태에서 ‘온셋 + 구성음 변화 가점’을 켜고 끄면 비교할 수 있다.** 기존 결과를 백업하고 별도 onset_context/onset_presentation 필드를 추가했으므로 재업로드는 필요 없다. 끄면 직전의 보수적 표시 정책으로 돌아간다.

## 처리 방식

- 온셋 활성만으로 전환을 만들지 않는다. 이전 약0.5초의 피치클래스 근거와 이후0.02~0.20초의 음 근거를 비교해 새 구성음이 나타나는지 확인한다. 같은 음집합을 반복 스트로크하면 전환 가점이 없다.
- 새 피치클래스 비중 .15 이상이며 그 음들의 온셋 활성 최대값 .5 이상일 때, 현재 오디오 후보 중 새 구성음을 지지하는 후보에 최대 .035의 양의 가점을 준다. 원시 1위에서 .06 이내인 후보만 대상이며 기존 가점·원시 점수는 보존한다. 선택 변경에는 기존 .025 차이 기준을 적용한다.
- 온셋 부재는 감점이나 전환 금지가 아니다. 온셋을 놓쳐도 기존 오디오·화성·표시 경로가 전환할 수 있다. 온셋 데이터가 없는 파일도 기존 경로로 처리한다.
- m7/6처럼 피치클래스가 같은 해석은 온셋만으로 구분하지 않는다. 분수코드·지속 저음의 보수적 표시 조건도 유지한다.
- 중앙 창과 이후 음 근거를 쓰는 사전 분석이며 실시간 무지연 방식이 아니다. 임계값·가점은 보정된 정답 확률이 아니다. 실제로 표시가 더 안정적이거나 정확해졌다는 결론은 아직 내리지 않았다.

## 기술 확인

6개 새 온셋 검사, 기존 표시·화성·웹 계약을 포함한 오프라인27개와 localhost HTTP3개가 통과했다. 프런트엔드 계약13개도 통과했다. 반복 스트로크·구성음 변화 없는 온셋·온셋 없는 실제 전환·같은PC 동점·원시 데이터 보존·켜기/끄기를 검사했다. 임시 HTTP 검사는 소켓 접근이 허용되는 실행 환경에서 별도로 실행했다.

기존4개 웹 작업의 원시 후보·기존 화성·직전 표시 결과가 그대로 보존됨을 대조했다. result_before_onset_v4.json에 직전 API 결과를 백업했다. 서버를 재시작하고 실제 v4 API 및 새 체크박스가 제공되는 것까지 확인했다. 브라우저 화면 조작은 자동 검수하지 않았다.

```powershell
python -m unittest test_onset_transition test_chord_presentation test_harmonic_context test_chord_web.WebContractTests -q
python -m unittest test_chord_web.HTTPTests -q
node test_chord_web_ui.js
python prepare_onset_review.py --apply
```

검수 시에는 같은 코드의 반복 스트로크에서 불필요하게 바뀌는지, 실제 전환을 놓치거나 늦게 표시하는지, 온셋 켜기/끄기 중 어느 쪽이 나은지를 확인한다. 이번 작업에서는 사용자 대신 음악적 검수나 새 정확도 평가를 하지 않았다.
