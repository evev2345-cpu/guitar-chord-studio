# GUITAR 개발일지 — 2026-11-03 현재 리뷰

하루 마감 기록은 [2026-11-03 마감 개발일지](DEVLOG_2026-11-03_END_OF_DAY.md)를 참고하세요. 아래 내용은 날짜 초반 리뷰 시점의 이력입니다.

시간 기준: Asia/Seoul. 주요 구현 파일·각 담당 보고서는 2026-11-02 작업이다. 이 문서는 날짜가 바뀐 뒤 11월 3일에 수행한 총괄 리뷰·재검증을 기록한다. 파일 시각과 보고서 기준으로 구분하며 11월 2일 구현을 11월 3일 신규 구현으로 집계하지 않는다.

## 목표와 전체 판정

첫 마일스톤을 기타 코드(chord) 후보 분석기로 확정했다. 장기 목표는 영상·오디오 기반의 수정 가능한 TAB 초안이다. 지판/프렛/현, 손, 오디오, 화성의 네 담당이 병행 개발하는 구조를 마련했다.

현재는 **각 분석 모듈의 기준선 구현 및 일부 영상 통합이 완료된 상태**다. 실제 오디오 기반 코드 분석, 현별 눌림·뮤트·개방 판정, 검증된 영상 추적은 아직 완료되지 않았다. 실행·단위검사 성공을 실연 정확도로 해석하지 않는다.

## 11월 2일 작업 기록

### 지판·프렛·현

- BAZE 지판 코너 검출, 평탄화, 프렛 관측·보간·경계 추정 경로를 유지했다. 기존 12장 end-to-end 결과의 지판 평균 IoU 약0.917은 과거 평가 결과이며 이번 리뷰에서 API 재평가하지 않았다.
- 로컬 현 검출을 추가하고 선 개수를 6개로 강제하지 않도록 수정했다. 화면상 선 순위와 실제 현 번호를 분리하고 물리 번호 미확정은 null로 남겼다.
- 고해상도 원본 직접 평탄화와 공통 좌표 변환, 지지 구간·연장 구간 구분, 원본/변환 출처를 저장했다.
- 영상 3프레임의 선명한 선 4개씩, 총12개 임시 수작업 참조에서 원본 오차 평균은 800×150 약0.71px, 고해상도 약0.59px였다. 참조 오차 약±1.5px, 에이전트 검수이며 독립 정답이 아니다. 6현 검출 정확도나 유의한 개선으로 주장하지 않는다.
- 프렛 라벨러는 삭제·정렬 후에도 물리 번호를 유지하도록 수정했다. 원본 예시를 보존하고 번호를 감사했으며 가린 부분은 미검증으로 남겼다.

### 손·프렛·현 통합

- 오픈 코드3장·바레2장·전환1장을 추출했다. 손끝 위치 분포, 복수 프렛 후보, 지판 밖/미해결 질량, 엄지, 검지 마디 구간을 출력했다.
- C♯m7 검지의 임시 시각 라벨 대비 약23.4px 오류를 회귀 fixture로 보존했다. 작은 반경의 분포가 잘못된 중심을 과신함을 확인했다.
- 전체 화면/ROI 검출 불일치·ROI 미검출·급격한 변화에 판단 보류를 추가했다. 임계값은 미보정 휴리스틱이다.
- 최신 현 출력과 원본 픽셀 해시·행렬·캔버스를 대조해 4개 장면의 통합 오버레이를 생성했다. 현 번호가 미해결인 선을 특정 물리 현으로 확정하지 않았다.
- 216.208~218.208초로 표시된 49프레임을 IMAGE 모드로 독립 추론했다. selected40, no_hands3, no_hand_near_board4, ambiguous2. PTS 정합 전의 프레임 기반 표시 시간이다.
- 지판을 프레임별 검증하지 않았으므로 해당 구간의 프렛 결정은 전부 보류했다. 영구 손 ID·평활화는 미구현이다.
- 독립 사람 검수는 0점이다. 6장×21점=126항목의 예측을 숨긴 검수 HTML을 만들었다.

### 오디오

- 원본3~12초를 native 44.1kHz stereo PCM 및 mono로 추출했다. manifest·파형/스펙트럼·onset·피크·chroma·음향 이벤트를 저장했다.
- 원본 video stream start_time=0.041667초, audio start_time=0을 확인했다. 이는 컨테이너 시작 PTS 차이며 실제 A/V 지연이 41.667ms라는 확정은 아니다.
- onset23개, spectral peak 레코드10,177개, chroma882프레임을 생성했다. 피크 수는 음표 수가 아니다.
- 배음/기본음 분리, 실제 청취, 수작업 onset·pitch·음향 사건 정답, 영상 스트로크 정합은 미완료다. 모든 실제 성능 지표는 미평가다.

### 화성

- 표준 라이브러리 기반의 튜닝·카포·상대/물리 프렛 음 계산과 15종 코드 사전·상위3개 후보를 구현했다.
- 구성음 일치·누락·추가에 따른 휴리스틱 점수, 전위의 확인된 베이스 요구, 모호성·증거 충돌·판단 보류를 출력했다.
- 손 위치 후보에서 발음 음을 만들지 않고 가능한 운지와 관측 음을 분리했다.
- Em7/G6 모호성, 카포1의 G 모양→A♭ 실음 등 합성 사례를 검증했다. 실제 오디오와의 연결·연주 코드 정확도 평가는 미완료다.

## 11월 3일 총괄 재검증

네 담당 채팅의 최신 완료 메시지, 실제 코드, 스키마, 보고서 및 산출물을 교차 확인했다. 외부 API·학습·새 음향 추론은 실행하지 않았다. 기존 결과를 덮어쓰지 않았다.

실행한 회귀 검사:

```powershell
python -m unittest test_baze_client test_fret_geometry test_hand_fret_tracker test_fingertip_probability test_chord_photo_validation test_hand_quality test_string_detector test_audio_analysis test_harmony_engine -v
```

**59개 통과, 실패0개.** 과거 현 테스트의 실패는 현재 파일에서는 재현되지 않았다. 다만 JavaScript 라벨 모델 검사는 이번 리뷰에서 재실행하지 않았다(Node 실행 명령이 PATH에서 확인되지 않음). 라벨러 실제 GUI 검수도 이번 범위 밖이다.

### 직접 재현한 통합 결함

`dataset/audio_analysis/runs/clip_003_012/evidence.json`을 `adapt_audio` 후 `harmony_engine.analyze`에 전달했다.

1. 실제 오디오의 `capo=null` 때문에 `AttributeError: 'NoneType' object has no attribute 'get'`가 발생했다. 화성 엔진은 capo 객체만 기대한다. 정상적인 unknown 입력을 크래시 없이 처리해야 한다.
2. 메모리에서만 capo를 unknown 객체로 바꿔 재시도하면 insufficient_evidence와 코드0개를 반환한다. 오디오의 최상위 `pitch_candidates`는 화성의 `evidence.observed_audio_notes`와 의미·구조가 다르다. 이 보류 자체는 타당하며, 스펙트럼 피크를 확정 음으로 복사하는 수정은 금지한다.
3. `rank_chords`에 E2/B2 두 음을 주면 세 pitch class 미만 조건으로 후보0개다. 사전에는 power chord가 있지만 현재 정책에서는 독립적인 두 음 파워코드 입력이 보류된다. 제품 지원 범위와 코드 사전을 일치시킬 정책 결정이 필요하다.

### 코드에서 확인한 경계 위험

- 손 프레임 시간은 `frame_index/fps`, 일부 초기 사례는 `/24`다. 오디오의 원본 시간과 통합하기 전 프레임 PTS를 검증해야 한다. 기존 시간을 무조건41.667ms 이동하는 수정은 금지한다.
- 현·손 내부 source_id에는 사례 이름이 쓰이는 경로가 있고, 오디오 공통 계약은 원본 MP4 SHA-256이다. 영상 해시·프레임 ID·decoded BGR 픽셀 해시·파일 해시를 별도 필드로 구분해야 한다.
- 실제 현 번호 미해결, 수동 지판 fixture, 사람 검수0점이 현별 상태 결합을 막고 있다. 오디오의 반복 피크와 서로 다른 시간의 음을 구간 전체에서 합치면 존재하지 않는 화음을 만들 수 있다.

이번 요청은 리뷰와 계획 수립이므로 위 구현은 임의 수정하지 않고 담당별 다음 작업으로 지정했다. 59개 검사가 실제 오디오→화성 연결 실패를 잡지 못한다는 점이 다음 회귀 검사 보강 근거다.
