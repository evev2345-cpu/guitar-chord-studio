# Chord Studio

기존 Python 오디오 분석기를 연결한 로컬 웹앱입니다. 타브는 다음 마일스톤으로 남깁니다.

```powershell
python chord_web_server.py --open
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 이미 실행 중이면 다시 서버를 띄울 필요가 없습니다. 다른 포트를 쓰려면 `--port 8766`을 붙입니다.

1. **샘플 들어보기:** 기존 194~226초 기타 분리음과 저장된 모델 결과를 불러옵니다. 새 추론은 하지 않습니다. 재생 시간 20초가 원본 214초입니다.
2. **파일 선택 / 드롭:** 오디오·영상 파일을 업로드합니다. 최대 150MB, 길이 0.5초~5분입니다. ffmpeg가 재생용 파일과 분석용 오디오를 준비하고, 기존 Basic Pitch ONNX 모델을 실행합니다.
3. 재생·탐색에 맞춰 현재 후보와 동점을 표시합니다. 실음/카포 기준 운지, 카포 0~12, 0.2/0.4초 창을 바꿀 수 있습니다. 타임라인을 눌러 이동하고 JSON을 내보냅니다.

‘저음·화성 가점 적용’을 켜면 지속 저음과 앞뒤 원시 코드 후보, 충분히 분명한 조성 후보로 제한된 가점만 더합니다. 분수코드의 분모도 카포에 맞춰 환산합니다. 끄면 기존 오디오 표시로 돌아갑니다. 근거가 약한 m7/6 등은 함께 남습니다. 실제 저음의 악기는 구분하지 못하며 분수 표기는 잠정 추정입니다. [실제 비교와 한계](../docs/HARMONIC_CONTEXT_2026-11-05.md)를 참고하세요.

현재 표시 정책은 약한 저음은 별도 후보로만 남기고, 강하게 지속되는 구성음일 때만 메인 분모에 붙입니다. 동점에 직전 해석이 포함되면 ‘동점 · 직전 해석 유지’로 표시합니다. 짧은 변화는 현재 오디오에서 이전 후보가 계속 지지될 때만 정리하며, 일부 빠른 실제 약한 전환이나 분수 진행은 보류될 수 있습니다. [표시 과민성 수정과 전후 영상](../docs/CHORD_PRESENTATION_2026-11-05.md)에 실제 변화 수와 한계를 기록했습니다.

‘온셋 + 구성음 변화 가점’은 저음·화성 가점을 켠 상태에서 비교합니다. 같은 구성음의 반복 스트로크에는 전환 가점을 주지 않고, 온셋과 새 구성음이 함께 잡힐 때만 현재 후보에 작은 가점을 더합니다. 온셋이 없어도 기존 전환은 가능하며, 끄면 직전 표시 결과로 돌아갑니다. [온셋 연결과 검수법](../docs/ONSET_TRANSITION_2026-11-05.md)을 참고하세요. 실제 정확도·체감 검수는 아직 사용자 확인 전입니다.

Mela에는 영상별 근사 지판 설정과 전체 화면 VIDEO 손 추적을 연결했습니다. ‘비전 위치 가점 · 실험’으로 비교하고 ‘손·가상 지판 보기’로 실제 관측 선을 확인합니다. **다른 영상은 지판 설정이 없으면 기존 오디오 결과를 유지합니다.** 현재 Mela와 동일한 원본 파일의 재업로드만 등록 설정을 자동 재사용하며 참조 프레임 픽셀을 검증합니다. 누름·뮤트·정밀 현/프렛 번호는 미확정입니다. [연결 범위·원본 사진·한계](../docs/WEB_VISION_INTEGRATION_2026-11-05.md)를 참고하세요.

서버는 기존 Python의 NumPy 등 프로젝트 의존성과 PATH의 ffmpeg/ffprobe를 사용합니다. 모델 추론은 `.venv-audio-model/Scripts/python.exe`와 기존 설치 모델을 재사용합니다. 새 패키지를 설치하지 않았습니다.

분석은 순차 실행되며 최대 4건까지 대기합니다. 결과·입력·모델 로그는 `webapp/runs/<job_id>/`에 남고 서버 재시작 후 완료 결과를 다시 열 수 있습니다. 실패 로그는 해당 폴더의 `analysis.log`에 있습니다. 서버는 `127.0.0.1`에만 바인딩하며, 서버를 실행한 터미널에서 Ctrl+C로 종료합니다.

## 현재 범위

- 사전 분석입니다. Mela에 한해 잠정 비전 위치 가점이 연결됐고, 미설정 영상·음원은 오디오 경로를 유지합니다. 기타 분리 자동화, 유튜브 URL 가져오기, 크롬 확장은 아직 연결하지 않았습니다.
- 업로드한 원음에 보컬·피아노가 있으면 그 음도 분석됩니다. 기타 분리음 입력을 권장합니다.
- 중앙 시간창·앞뒤 표시 정리를 사용합니다. 실시간 스트리밍 분석이 아닙니다.
- 동점은 함께 표시하며, 순위 점수를 정답 확률로 표시하지 않습니다. 상위 3개를 보여주므로 동점 개수가 더 많을 수도 있습니다.
- 원본 입력에서 파형 주파수 컷을 추가하지 않습니다. 기존 D2~E6 음 후보 범위와 코드 채점·표시 정리를 재사용합니다.
- 공개 배포용 인증·운영 서버가 아닌 로컬 프로토타입입니다. 외부 인터페이스에 노출하지 않습니다.

## API

`POST /api/jobs?name=<이름>`에 파일 바이트를 본문으로 전송하면 작업 ID를 반환합니다. `POST /api/demo`는 빈 본문으로 샘플을 만듭니다. `GET /api/jobs/<id>`의 상태가 `complete`가 되면 `result_url`, `media_url`을 사용합니다. 결과의 시간은 **업로드한 파일의 재생 초**이며 카포는 화면 표기에만 적용됩니다. 상태는 `uploading → queued → running → complete/error`입니다.

```powershell
python -m unittest test_chord_web -q
node test_chord_web_ui.js
```

브라우저 자동 접근 승인 단계가 차단되어 실제 렌더링·브라우저 재생은 자동 검수하지 못했습니다. HTTP 업로드, 실제 모델 추론, 결과 JSON, 미디어 바이트 범위 탐색과 프런트엔드 표기 계약을 별도로 검증했습니다.
